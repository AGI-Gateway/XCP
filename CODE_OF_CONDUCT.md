# Code of Conduct

## Our standard

This project is a working space. Be direct about technical disagreements and
decent to the people you disagree with. Assume competence and good faith.

Specifically, we expect:
- Critique of ideas, code and claims — including ours. Especially ours.
- No harassment, personal attacks, or demeaning comments.
- Respect for people's time: search before asking, give reproducible reports,
  and accept "no" without relitigating it.

## Security-relevant honesty

Because this is a trust and security project, one norm matters more than usual:
**do not overstate what the software guarantees.** Marketing claims in issues,
PRs or docs that a mechanism "solves" a threat class it only mitigates will be
asked to be reworded. This applies to maintainers first.

## Enforcement

Report concerns via GitHub's private vulnerability reporting on this
repository, which reaches the maintainers without deanonymising anyone. Maintainers will respond, keep the
report confidential to the extent possible, and may warn, temporarily block, or
permanently ban for serious or repeated violations.

Adapted in spirit from the Contributor Covenant, kept short deliberately.
